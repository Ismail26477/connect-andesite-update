WHY THESE ARE STRUCTURED DIFFERENTLY FROM SUPABASE:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

SUPABASE Variables (with VITE_ prefix):
  ✅ VITE_SUPABASE_URL
  ✅ VITE_SUPABASE_PUBLISHABLE_KEY
  
  → VITE_ means "exposed to browser"
  → These are PUBLIC keys (safe to expose)
  → Can be seen in browser code

MONGODB Variables (NO VITE_ prefix):
  ❌ MONGODB_URI (no VITE_ prefix!)
  ❌ MONGODB_DB_NAME (no VITE_ prefix!)
  
  → No VITE_ means "kept secret" (server-only)
  → Contains credentials (username:password)
  → NEVER exposed to browser
  → Only accessible in server code

HOW YOUR APP USES THESE VARIABLES:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Supabase Variables (Used Directly):
  
  Browser (React)
    ↓
  Import supabase client
    ↓
  Use VITE_SUPABASE_URL
    ↓
  Make requests to Supabase
  
  Why? Supabase uses public keys + token-based auth

MongoDB Variables (Server-Only):

  Browser (React)
    ↓ (Calls server function)
  Server Function (Node.js)
    ↓
  Access MONGODB_URI
    ↓
  Connect to MongoDB
    ↓
  Query database
    ↓
  Return data to browser
  
  Why? MongoDB requires keeping credentials secret

WHERE THESE ARE USED IN YOUR CODE:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

MONGODB_URI:
  Location: src/lib/mongodb.ts
  Used in: getDatabase() function
  Purpose: Connects to MongoDB cluster
  
  Code:
    const mongodbUri = process.env.MONGODB_URI;
    const client = new MongoClient(mongodbUri);

MONGODB_DB_NAME:
  Location: src/lib/mongodb.ts
  Used in: getDatabase() function
  Purpose: Selects which database to use
  
  Code:
    const dbName = process.env.MONGODB_DB_NAME || "bni";
    const db = client.db(dbName);

MONGODB_COLLECTION_MEMBERS:
  Location: src/lib/api/members.server.ts
  Used in: Server functions
  Purpose: Specifies the members collection
  
  Code:
    const collection = db.collection('members');
